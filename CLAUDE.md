# Герои полуострова

Браузерная пиксельная игра про путешествие по Кольскому полуострову: экран 320×240, масштаб ×1/×2/×4, сюжет из заставок, экранов-историй, вопросов «Да / Нет» и мини-игр (гонки, лагерь, медведь, заброшка, лавка, обмен, платформер). Чистые HTML, JavaScript и Canvas, без сборщика. Цель: собрать игру целиком и держать её опубликованной по адресу https://alexeytomilov.github.io/HEROES1/.

Подробное описание настроек, панелей и ассетов в `README.md`. Состояние работы и следующие шаги в `HANDOFF.md`.

Проект живёт в двух местах: в облачных сессиях Claude Code (клон репозитория с GitHub) и локально в `D:\PROJECTS\KOLSKIY\GAME\HEROES1` внутри проекта ролика «Кольский». Общий источник правды: репозиторий на GitHub. Облачная сессия не видит диски локального компьютера, а локальная видит только свою папку, поэтому обмен идёт через `git push` и `git pull`.

## Где что лежит

- `dist/` - вся игра, публикуется как есть.
  - `dist/index.html` - полная игра; `intro.html`, `map.html`, `race.html`, `rpg.html`, `waterfall.html` - отдельные просмотры и встроенные уровни.
  - `dist/full-game.js` - экраны, сюжет, карта, переходы, клавиши; `dist/full-bridge.js` - встроенные уровни в iframe, пауза, «Назад», таймер показа экранов.
  - `dist/current-ui.js` - пиксельная вёрстка экранов; `dist/text-presets.js` - пресеты и правки текста; `dist/color-presets.js` - зоны фона.
  - `dist/story.js` - сюжет: все экраны, их тексты, переходы, вопросы. Игра берёт текст экранов отсюда.
  - `dist/level-texts.js` - все тексты внутри уровней: у каждого `text` и `when` (когда появляется), у уровня `title` и `logic`. В коде `LT('уровень.ключ', {переменные})`.
  - `dist/trip-engine.js` + `dist/race.js` - гонки (режимы `sredny`, `fog`, `home`); `dist/rpg.js`, `dist/camp.js`, `dist/shop.js`, `dist/platform.js` - остальные уровни.
  - `dist/project-config.js` - начальные настройки проекта; `dist/assets/` - PNG, шрифты, слои; `dist/assets/screens/` - фоны экранов, заставки, фото экрана 2.3.
- `tools/` - скрипты: выгрузка слоёв из PSD (`extract-intro-layers.py`, `extract-screen23-photos.py` и др.), генерация схем для Miro (`story-to-miro.cjs`, `level-texts-to-miro.cjs`), сервер `serve.mjs`.
- `tests/` - тесты переноса настроек.
- `.github/workflows/pages.yml` - публикация на GitHub Pages; при сборке номер коммита подставляется во все `?v=` и в `__BUILD__` в `dist/full-bridge.js`, чтобы браузер не брал старый кэш.

## Правила и договорённости

- Общение по-русски, коротко, без длинных инструкций для пользователя.
- После каждой правки сразу выкладывать игру: коммит, push, PR в `main`, слить PR, дождаться успешного workflow «Publish game to GitHub Pages», дать ссылку https://alexeytomilov.github.io/HEROES1/ (обновлять через Ctrl+F5). Не давать пользователю список действий вместо результата.
- Перед работой обновлять `main` и читать свежий `README.md`: в `main` параллельно пишут другие сессии (ветки `claude/*`, `codex/*`). Если PR рабочей ветки уже слит, начинать новую работу с ветки от свежего `main`. Конфликты обычно в строках `?v=` в HTML, их можно разрешать в пользу любой стороны.
- Доска Miro всегда должна совпадать с игрой. Меняются тексты или экраны, которые есть на доске, значит обновить и доску. По просьбе «синхронизируй Miro» переносить правки с доски в `dist/story.js` и `dist/level-texts.js`, затем выкладывать.
- Новые тексты в уровнях добавлять в `dist/level-texts.js` с описанием `when`, а не строкой в коде.
- Подсказок по клавишам под игрой нет и не должно быть. Служебные подписи для экранного диктора и панели настроек оставляем.
- Перед выкладкой сверять экраны с прежней версией: заметные изменения должны быть только там, где их просили.
- Служебные записки и отчёты для пользователя давать текстом в чат, а не файлами в случайных папках.

## Запуск и проверка

- Нужен Node.js 20+. `npm start`, затем http://127.0.0.1:8080/. Открывать только по HTTP.
- `npm test` - тесты настроек, строка `PASS` на каждый пройденный файл тестов. Состояние тестов в `HANDOFF.md`.
- Проверка в браузере через Playwright. Только в облаке: Chromium уже стоит в `/opt/pw-browsers`, `playwright install` не запускать. Экран выбирается в `#chapter-select` по коду (`2.3`, `drive1`, `shop3`...), автопоказ останавливается кнопкой `#scene-pause`, скриншот снимать с `#frame`. Встроенный уровень можно открыть отдельно: `race.html?embed=1&mode=sredny`.
- Сравнение со старой версией: `git worktree add` старого коммита, раздать его вторым сервером на порту 8081 и сравнить скриншоты всех экранов из `#chapter-select`. Лагерь `camp1` всегда отличается: туристы расставляются случайно.

## Локальный запуск (Windows)

- Нужны Node.js 20 или новее (https://nodejs.org/, ставится вместе с npm) и Git для Windows.
- В папке `D:\PROJECTS\KOLSKIY\GAME\HEROES1` выполнить `npm start` и открыть http://127.0.0.1:8080/. Сервер `tools/serve.mjs` слушает только 127.0.0.1, порт 8080 задан в нём; если порт занят, закрыть другую программу или поменять число в `tools/serve.mjs` только у себя.
- Двойной щелчок по HTML не работает: игре нужен HTTP для загрузки JSON.
- `npm test` запускается так же. Зависимости не нужны, `npm install` не требуется.
- Для Playwright локально: `npm i -g playwright` и `npx playwright install chromium`. Скрипты проверки держать вне проекта.
- Для скриптов из `tools/*.py`: Python 3 и `pip install psd-tools pillow numpy`.
- Перед работой `git pull`, после работы коммит и `git push`, чтобы облачные сессии видели правки.

## Только для облачной среды

- Путь `/opt/pw-browsers` и запрет `playwright install`.
- Коннекторы Google Drive и Miro: подключаются в https://claude.ai/customize/connectors и подхватываются новой сессией.
- Публикация через PR делается инструментами GitHub в сессии; локально то же самое делается обычным `git push` и PR на сайте GitHub.

## Работа с инструментами

- Google Drive: `download_file_content` отдаёт base64 в JSON, большой ответ сохраняется в файл: `jq -r .content файл | base64 -d > имя.psd`. Коннектор обрывает файлы около 10 МБ. Для разбора PSD `pip install psd-tools`.
- Miro: большие ответы сохраняются в файл, разбирать через jq или python. Правка через `canvas_update_from_svg` требует `data-scope` и `data-baseline-hash` из самого свежего чтения той же области, иначе отказ «area has changed». Большие SVG отправлять частями. Масштаб элементов ×12 под размер доски.
